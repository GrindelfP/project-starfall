# Asteroid flight sandbox

The default seed is `1398030674` (`0x53544152`); `--seed <uint32>` selects another decimal seed. The seed is logged and shown in the control panel. A fixed integer generator creates 64 rocks in a bounded region; reset (`R`) regenerates the same field, restores the ship and camera, and clears the contact counter. The spawn has at least 10 world units of clearance beyond the two collision spheres. `C` toggles chase/free camera; the panel lists the remaining controls. `--demo` flies a fixed-step path for repeatable bounded runs.

Each rock uses two differently rotated cubes centered on its collision sphere. The sphere encloses both cubes. The ship uses a conservative radius 1.8 sphere; touching counts as contact. On contact the ship returns to its safe starting pose and the visible counter increments. This is a discrete position check, not swept collision: a sufficiently fast ship or large time step can pass through a rock between checks. Collision and field data are CPU-side and independent of either renderer.

The sandbox draws 64 rocks (128 cube draws), 96 star points, four beacons and seven ship parts, for 235 draws with the shared eight-vertex, 36-index cube. Geometry buffer payload is 96 bytes of vertices plus 72 bytes of indices. DX11 also has an 80-byte constant buffer; DX12 uses root constants and two committed upload resources for the geometry (allocation granularity can make the actual memory commitment much larger than the 168-byte payload). These figures exclude swap-chain/depth surfaces, driver overhead and optional capture readback; no per-rock GPU mesh is allocated.

Debug and Release CTest passed 5/5 including seed reproducibility, spawn clearance, tangent contact, separation and reset layout. Bounded 30-frame Release demos completed on DX11 and DX12; a Debug DX11 demo also completed. GPU captures show the ship and obstacle field; the native help panel is outside those captures. Interactive controls, collision response, reset and free-camera inspection still require a manual desktop check. The bounded runs establish successful presentation, not a 60 FPS measurement.
