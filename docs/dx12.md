# DirectX 12 reference renderer

Select `--backend dx12 --scene reference`; `--backend dx11` is the default. Both use the same reference objects and camera. `--clear-only` selects the DX12 clear path; `--depth-check` is currently DX11-only. `--frames N` and `--lifecycle-test` are bounded correctness runs.

CMake locates the Windows SDK x64 `dxc` and compiles `shaders/scene12.hlsl` as `vs_6_0` and `ps_6_0` into the ignored build directory. The build reports compiler diagnostics directly. DX11 continues compiling its own SM5 shader. Debug requires Windows Graphics Tools; it enables the DX12 debug layer and GPU-based validation. Messages and a live-device report are written to the diagnostics log next to the executable.

One direct queue, command allocator and command list are reused serially. Each frame transitions the current swap-chain buffer PRESENT -> RENDER_TARGET, clears and draws indexed cubes with depth, transitions it back to PRESENT, submits and presents. A fence is signaled and waited before allocator reuse. Vertex and index data remain in upload heaps for their entire GPU lifetime; object matrices and colors are root constants copied into the command stream. Resize waits for the queue before releasing back buffers and depth, then recreates descriptors and projection. Shutdown also waits before releasing resources. This intentionally favors correctness over throughput.

`--capture path.bmp` writes a one-frame uncompressed BMP using a synchronous GPU readback for visual correctness checks; do not include capture runs in timing measurements. Captured reference pixel channels matched DX11 exactly on the GTX 1050 in the verified run. Debug and Release DX12 captures also matched.
