# 0004 - DX11 shader build and first triangle

Name: DX11 shader build and first triangle
Status: done
Dependencies: 0002-window-resize-and-lifecycle.md.

## Description

Add the first real graphics pipeline: a vertex buffer, input layout, HLSL vertex/pixel shaders, explicit pipeline state and a triangle draw. Establish a reproducible DX11 Shader Model 5 compilation path using the installed compiler tools or D3DCompile. Choose and document the build-time/runtime compilation approach before implementing it; avoid adding a new shader toolchain dependency.

Keep shader sources versioned and generated bytecode ignored. Resolve shader paths predictably when launching from both the repository and build directory. Compiler failures must identify the shader, entry point and compiler diagnostics. Use an asymmetric colored triangle so orientation and vertex attributes are observable.

## Acceptance criteria

- A clean build/run displays the expected triangle on the selected NVIDIA adapter in Debug and Release.
- Editing a shader causes the appropriate rebuild/reload using documented commands.
- A deliberate shader syntax error produces an actionable diagnostic instead of a blank silent failure.
- Generated shader products remain outside tracked source files.
- Capture a manual result and verify no application-caused debug-layer errors.

## Boundaries

No textures, materials, hot-reload framework, mesh importer or DX12 bytecode reuse. DX12 shader handling is addressed separately in 0009.

## Verification (2026-11-15)

Debug and Release configured and built with the documented presets. Both were visually checked on the NVIDIA GeForce GTX 1050: the asymmetric triangle showed smooth red, green and blue vertex color interpolation. Both closed normally. The Debug run presented 3392 frames and the debug layer reported no messages before the live-object report; that report listed only the expected device.

Touching the versioned HLSL triggered the shader copy in both builds, and copied files matched the source hash. An isolated Debug executable with a deliberately invalid copied shader exited with code 1 and logged its filename, `VSMain`, `vs_5_0`, line and compiler error; restoring the shader produced a clean two-frame run. See [shader instructions](../shaders.md) for the runtime compilation and rebuild contract.
