# Frame timing and native input

The loop uses `std::chrono::steady_clock`. `FrameTimer::tick` returns seconds for a variable-step update, clamped to 0.1 seconds; the first tick and the first tick after `reset` return zero. Minimizing or losing focus pauses the loop and resets the timer; it waits for Windows messages while paused. This is a small variable-step policy, not a fixed-step simulation. The title shows the frame delta in milliseconds. Update CPU time covers message processing, resize and the timer; submit/present CPU time is the preceding call to the renderer's present operation and may include synchronization waiting. Neither is GPU time; title formatting is outside the update measurement.

`InputState` stores Win32 virtual-key codes 0–255. Held persists until release; pressed and released are independent one-frame flags, including when both transitions occur in one frame. Auto-repeat does not generate another press. The application clears held state and accumulated mouse movement on focus loss or minimization. A future update can consume the state after messages have been dispatched and before the next `beginFrame`; no movement or camera behavior is implemented here.

Right-click the client area to capture the mouse; Escape, focus loss or capture loss releases it. Relative raw mouse counts are accumulated per frame while captured and focused; absolute raw devices are ignored. The title displays numeric Win32 virtual-key codes, press/release flags, relative counts and capture state. Values are live and one-frame transitions can be brief. Input and timing behavior have no external library dependency.

Run `ctest --test-dir out/build/debug --output-on-failure` and the equivalent release path after building. The tests exercise transition edges, repeated keys, focus clearing, mouse accumulation, delta clamping and reset. For interactive validation hold a key, alt-tab away and back, right-click and move the mouse, press Escape, and minimize/restore. Check that held state clears, capture releases and the restored delta does not jump. Automated lifecycle runs and these unit tests do not substitute for that manual check.

Visible Debug verification on 2026-11-15 confirmed right-click capture and Escape release, W press/release without a stuck held key, and Alt-Tab focus loss followed by reactivation and resumed rendering with delta below 100 ms. Diagnostics recorded a clean shutdown after 3392 frames. Holding W continuously through Alt-Tab was not manually exercised; the unit test covers clearing a held key.
